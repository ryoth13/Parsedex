# Parsedex

Parsedex 是一款基于 Tauri、Vue 和 Vite 构建的协议报文解析工具。输入十六进制报文后，工具根据已配置的匹配规则识别协议，并提供协议文档入口与对应的解析页面，帮助开发者查看报文结构和字段含义。

本项目提供软件框架及 Demo 协议示例。厂商定制协议的匹配规则与解析脚本需要使用者自行编写和接入。

## 功能介绍

- **协议识别**：根据报文特征、长度、校验等自定义规则匹配已接入的协议。
- **字段解析**：按字段展示原始数据与解析结果，便于调试和排查报文问题。
- **协议文档**：从识别结果打开对应的协议 PDF。
- **扩展解析能力**：通过 JavaScript 添加协议匹配和解析逻辑，复用现有页面。
- **辅助工具**：提供常用的数据处理及加解密函数，供解析脚本调用。

## 快速体验

启动开发环境后，在首页输入以下 Demo 报文：

```
672067676767006767C1056767600900EE16
```

执行搜索，选择“点击解析数据”查看字段解析结果；选择“点击查看协议”打开示例文档。

## 本地开发

### 开发环境

- Bun：安装前端依赖并运行项目命令。
- Rust 工具链及当前操作系统所需的 Tauri 构建依赖：用于桌面应用开发和打包。
- Windows 桌面开发还需要 Microsoft C++ 构建工具与 WebView2 运行环境。

仅预览前端时，无需编译 Rust。窗口控制等依赖 Tauri 的能力需要在桌面环境中使用。

### 安装依赖

在项目根目录执行：

```
bun install
```

### 前端预览

```
bun run dev
```

默认地址为 `http://localhost:1412/`。如需使用其他端口：

```
bun run dev --port 4000
```

此时访问 `http://localhost:4000/`。桌面开发使用 Tauri 配置中的默认端口 `1412`。

### 桌面开发

```
bun run tauri dev
```

该命令会自动启动前端开发服务器，并启动 Tauri 桌面窗口。

## 构建

### 前端构建

```
bun run build
```

构建输出位于 `dist/`。当前构建命令会在生成后删除 `dist/pdf/`，因此该命令生成的产物不包含协议 PDF；如需在构建版本中查看文档，需要自行调整文档分发方式或构建命令。

预览前端构建产物：

```
bun run preview
```

### 桌面应用打包

```
bun run tauri build
```

默认打包输出位于 `src-tauri/target/release/bundle/`，具体安装包格式取决于操作系统与打包配置。

## 添加自定义协议

新增协议通常需要准备匹配规则、解析脚本，以及可选的协议文档。

| 路径                           | 用途                                 |
| ------------------------------ | ------------------------------------ |
| `public/script/allinone.js`    | 编写协议识别规则，返回对应的解析配置 |
| `public/js/`                   | 存放各协议的 JavaScript 解析脚本     |
| `public/pdf/`                  | 存放协议 PDF 文档                    |
| `public/script/fuctionDuel.js` | 通用数据处理与校验函数               |
| `src/components/ParseTool.vue` | 解析页面及协议脚本加载逻辑           |

### 1. 编写解析脚本

参考 `public/js/demo协议解析.js`，在 `public/js/` 下创建自己的脚本。当前页面通过全局函数 `window.parseData()` 触发解析，脚本需沿用 Demo 的输入、输出元素约定。

需要自行实现的内容包括报文校验、字段偏移和长度、字节序、数值转换，以及字段含义等。通用函数可参考 `public/script/` 下的现有实现。

### 2. 添加识别规则

在 `public/script/allinone.js` 的 `parsePro()` 中添加匹配分支。建议综合使用帧头、帧尾、数据长度和校验结果，避免仅凭单个字节识别协议。

匹配成功后返回以下配置：

```
return {
  protype: "自定义协议",
  prolink: "自定义协议.pdf",
  parsetitle: "自定义协议解析",
  ifkey: false,
  usejs: "自定义协议解析.js"
};
```

| 字段         | 说明                                             |
| ------------ | ------------------------------------------------ |
| `protype`    | 首页识别结果显示的协议名称                       |
| `prolink`    | `public/pdf/` 下的协议文档文件名                 |
| `parsetitle` | 解析页面标题                                     |
| `ifkey`      | 是否显示密钥输入区域；解密逻辑仍需由解析脚本实现 |
| `usejs`      | `public/js/` 下的解析脚本文件名                  |

当前首页的解析入口与协议文档入口存在关联；接入时可先沿用 Demo 配置完整的文档与解析脚本。若不提供文档，需要同步调整 `src/views/Home.vue` 中的入口显示逻辑。

### 3. 添加文档并验证

将对应文档放入 `public/pdf/`，确保返回配置中的文件名与实际文件一致。使用已知报文检查识别、文档打开和字段解析，并检查不完整报文、错误校验及不匹配输入的处理结果。
